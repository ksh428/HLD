SAGA DESIGN pattern is used for migration from monolith to microservices
IT IS USED TO MANAGE Distributed TRANSACTIONS ACROSS MULTIPLE MICROSERVICES TO ENSURE DATA CONSISTENCY

 It mainly solves acid properties for a distributed non shared db system: each micro svc has its own db and the contract is
each svc can directly call only its own db, but if it needs some other db, it will make an api call to the respectives 
microservice and get the value instead of calling its db.

[SAGA Type: CHOROEGRAPHY]
It works on events, each serivce send out a success or failed event to a queue and the dependent service listens on that 
particular event, and performs roll forward or roll back based on that

[SAGA Type: ORCHESTRATOR]
There is a central component called orchestrator which calls each svc and looks for its result,if it succeeds it calls the next svc else rolls back
as appropriate.

WHEN TO USE:
1. Microservices with all or nothing flow .
2. Keep DB's in sync.
3. Dealing with long-running processes: When a transaction takes seconds or minutes to complete
