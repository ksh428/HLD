KQL:

What is index:
It is a data structure which lets the db locate rows without scanning the entire table

Lookup time ->O(logn)

Why Db's use B+ trees instead of hash maps:

Hashmaps are efficicent for point searches but not for range based queries, cannnot sort, weak in prefix
searches

DBMS: tries to create clustered index on PK, but if it is not there it woulod create an internal column similar to PK
and use it for clustered index

LEFT MOST PREFIX rule in case of composite indexes
