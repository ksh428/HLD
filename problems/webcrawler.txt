Webcrawler:
It is a program which automatically traverses the web by downloading web pages and following links from 1 page to another.

Problem:
Design a web crawler to extract text data from the web and store it to train a LLM, and it can run only for 5 days.

Functional requirements:
1. Crawl the web from seed urls.
2. Extract the data and store.

NOTE: IN data processing systems,think of multiple stages in a pipeline instead of services.

Scale:
10 B web pages 
2MB per page

Non functional requirements:
-fault tolerant
-politeness [adhere to robots.txt for the webpage]
-scale to 10B pages 

Core Entities:
-Text data 
- URL metadata
- Domain metadata

Interface:
input: set of seed urls 
output: text data 

Data flow:
1. take seed urls from the frontier urls set and the IP from DNS.
2. fetch HTMl.
3. Extract text from HTML.
4. Store that text in DB.
5. Extract the urls in the text and add to the frontier set.
6. recursively continue until all the urls in frontier have finished.

HLD:

The frontier queue can be kafka/Amazon SQS


Deep dives:

We can use Amazon SQS, this supports retires with exponential backoff.
So, we can manintain a list of failed urls (to fetch) and use this feature.
