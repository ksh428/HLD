Functional Requirements:
1. Users should be able to upload videos
2. watch/stream videos

Scale:
1M Uploads/day 
100M DAU 
Max video size: 256 GB

Non func requirements:
- AAvailability >> consistency. we are okay to delay showing new videos for some time 
- support uploading and stream large videos (256 GB)
- low latency streaming < 500ms.
- should be scalable according to the above section.

Core Entitites:
1. Video
2. Video Metadata 
3. User

    metadata [containing size]

HLD:
Just know about the following:
video codec
bitrate 
video container 

chunks are playable units of a video typically a few seconds long

4GB is the limit in case of Azure App Gateway
Upload the video directly to AZ blob storage using presigned urls (the video service requests for these
urls given the size of the file to be uploaded), use chunking and PUT BLOCK API (azure)

Once the video is uploaded successfuly, the blob storage sends out a Blob created event , which can be processed
by azure functions to update the db 

Handling video playbaacks in lower resolutions:
We can transcode the video for different bitrates/resolutions asynchronously and store them in  s360, so whenever a particular
resolution is selected, we get from that particular array [Manifest file].
For video streaming the client downloads the manifest file and selects a bit rate based on filter by user 
or network conditions, and starts adaptive streaming.

Resumbale uploads/downloads: use chunk fingerprinting to identify chunks for resum download/upload and for security 
verify it with the fingerprint stored in the db.
