Primary keys:

Partition key: unique identifier that determines items physical storage location using
consistent hashing 
Sort key: (optional) secondary attribute that enables orderging and range queries within a partition

Primary key: {partition key}:{sort key}


Examples:
system      partition key           sort key
chat app    chat id                 message id (monotonically increasing)
                                    we can't use timestamp, because chat id: timestamp might not 
                                    be unique , hence not a pk, so we can maintain the msg id's in increasing order 

e commerce  user id                 order id (mono increasing)


Secondary Indexes:
GSI (Global Secondary Index) : secondary attribute to query other than partition key
Local Secondary Index: same partition key but different sort key for alternate sorting
