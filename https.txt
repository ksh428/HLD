HTTPS:
Secure communication

Steps:
1. browser establishes a tcp connection with the server

2. tls handshake begins:
client hello -> the client sends out the following details
what tls version does it support , what cyber suites it supports
and in response to it , the server sends back a hello
The server sends out the cert to the client -> sends the public key ->Asymmetricc encryption and the cert
server hello done 

The data encrypted on the client side with the public key of the server can only be decrypted by the server
using the pvt key

3. client key exchange (RSA, tls 1.3 uses Diffie hellman mandatorily)
client generates its own symmetirc key and encrypts this key using the public key recieved from the server
this key is sent out to the server and decrypted back at the server using its own private key

4. data exchange
The data is encrypted by the session key and sent out and the server decrypts it using the same session key
recieved at the prev step -> Symmetric encryption (AES)

SSL certs:
There an additional step which the server does whil sending out the public key, it generates a SSL
cert from a trusted org , and along with the public key sends to the client
The ssl cert also contains the signature : Public key of server + public key of Trusted org

Now its the clinet's turn to verify the public key of the server, for that it fetches the public key
of the trusted org, and generates a signature of the recieved public key and trusted org public key
if it matches with the signature in the SSL cert -> fine
